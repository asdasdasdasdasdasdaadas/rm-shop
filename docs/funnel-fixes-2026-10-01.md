# Исправления по аудиту воронки — 1 октября 2026

Реализованы пункты 3–10. Обязательное приветствие, «Я помогу», подписка на канал и правила начисления/расходования подарка (пункты 1–2) сохранены.

## Поведение

3. После оплаты первой кнопкой идёт «Открыть кабинет». Реферальная кнопка остаётся вторичной для уже подключавшихся клиентов, если программа включена. Режим тишины убирает реферальную кнопку и призыв из подтверждения оплаты. В подтверждении показан актуальный баланс; нет безусловного обещания восстановления при недоступной панели.
4. Зачисление, журнал баланса, признак оплаты и состояние заказа фиксируются одной транзакцией. Уникальная квитанция защищает от повторов. Для Stars запись charge ID тоже входит в транзакцию. Старые обработанные платежи повторно не начисляются. Побочные действия имеют сохраняемую очередь с повтором после ошибки; реферальные начисления и бонус приглашённого идемпотентны. Условия программы фиксируются при зачислении, акция определяется по времени оплаты, чтобы задержанный повтор не участвовал в новой акции задним числом.
5. Незакрытая поддержка, включая pending, блокирует маркетинг. Отметка help сбрасывается только при отсутствии незакрытых обращений и онлайне позже обращения/закрытия последнего тикета как минимум на час. Формальное закрытие без последующего использования не считается восстановлением.
6. На экране низкого баланса есть минимальное пополнение. Для первой оплаты выбирается 100 ₽, если разрешено настройками; для повторной — 300 ₽, иначе первый доступный вариант. Показываются срок на текущее число устройств и произвольная сумма. При нулевом остатке и ещё оплаченном доступе используется состояние предупреждения. Автопоказ ограничен разом в сутки для каждого состояния и пользователя в браузере; переход от предупреждения к фактическому отключению допускает отдельный показ.
7. Автоматические сообщения, ручные рассылки, повторные отправки и анонсы акций используют резервирование частотного лимита в БД: до одного необязательного сообщения за 24 часа и трёх за 7 дней. Незакрытый тикет, help, режим тишины и недавняя оплата блокируют маркетинг. Ручные рассылки показывают число пропущенных получателей. Анонс акции откладывается в очереди и повторяется, пока акция действует. Платежи, предупреждения о балансе и непосредственное сообщение после добавления устройства не расходуют рекламный лимит.
8. Напоминание о подарке различает незавершённое приветствие, отсутствие подписки на канал и переход к подарку. Информация о тарифе отправляется после успешного использования, с фильтрами активности и поддержки. Убраны обвинительная формулировка и обещания доступности в любой сети. Предупреждение о балансе содержит остаток, число устройств и суточный расход. Сохранённые копии прежних стандартных текстов обновляются автоматически; собственные тексты администратора сохраняются.
9. Подстановки имени, бренда, ошибок и ссылок экранируются при формировании HTML. Разметка администраторского шаблона сохраняется, уже экранированные значения не экранируются дважды.
10. Из редактора убраны неактивные цепочки, их сохранённые значения не удаляются. В тесте воронки видны условия, исключения, отправки/ошибки за 7 дней и последняя отправка по типу сообщения. Общие типы имеют общую статистику. Админский тест остаётся безопасным предпросмотром. Реальные SQL-условия и транзакции проверяются отдельными изолированными интеграционными сценариями.

## Проверка

- Обычные Python-тесты: `python -m unittest discover -s tests`.
- Интеграционные тесты используют PostgreSQL в WASM (PGlite 0.5.8), временную базу и имитации Telegram/панели. Установить пакет в отдельный временный каталог: `npm install --prefix /tmp/rm-funnel-pg @electric-sql/pglite@0.5.8`.
- Затем: `PGLITE_MODULE=/tmp/rm-funnel-pg/node_modules/@electric-sql/pglite/dist/index.js NODE_BIN=node python -m unittest discover -s tests`.
- Без PGLITE_MODULE интеграционные сценарии явно пропускаются. В этой проверке они запускались.
- Сценарии: повторные RollyPay/Stars, исторические платежи, откат при ошибке учёта, сохранение возможности повторить Stars, повтор побочных действий, отсутствие участия в новой акции задним числом, подарок → настройка → первый онлайн → оплата, фильтры поддержки, частота и восстановление после ошибки отправки.
- Frontend: `node --test tests/*.cjs`; админка: `npm --prefix admin-ui run check`, `npm --prefix admin-ui run build`, `node admin-ui/tests/smoke.cjs`.

Это не отправка сообщений реальным клиентам и не нагрузочный тест нескольких PostgreSQL-серверов. Передача платежа от реального провайдера и доступность VPN-панели требуют проверки на развёрнутом сервисе. Изменения схемы выполняются при запуске через существующий init_db.

## Обновление сервера

Из каталога проекта: `git pull --ff-only`, затем `docker compose up -d --build bot`. Проверить `docker compose logs --tail=100 bot`. Локальная проверка и git push не означают, что сервер уже обновлён.
