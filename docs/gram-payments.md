# Прямая оплата GRAM (TON)

Получатель по умолчанию: `UQBuU8RCIxH121MjJofAC2xyvn-7pr2LmdqIiO5d_xVkkGgT` — адрес, предоставленный владельцем сервиса. Это нативная монета основной сети TON, не jetton с названием GRAM. Приватные ключи не нужны и не хранятся.

## Настройка

- `GRAM_WALLET`: публичный адрес TON mainnet, с проверкой контрольной суммы. Пустая строка скрывает метод для новых счетов. Старые счета продолжают проверяться по сохранённым кошелькам.
- `GRAM_COINGECKO_API_KEY`: необязательный Demo API key CoinGecko.
- `GRAM_TONCENTER_API_KEY`: необязательный ключ Toncenter для увеличения лимитов.
- В настройках способов оплаты включается/выключается «GRAM (TON)». Метод добавлен включённым, но скрывается без корректного адреса.
- После обновления зависимостей и перезапуска стандартная инициализация БД создаст таблицы. Цикл проверки запускается вместе с ботом.

## Курс и перевод

Курс RUB берётся через CoinGecko `/api/v3/simple/price?ids=the-open-network&vs_currencies=rub&include_last_updated_at=true`. ID соответствует GRAM: https://www.coingecko.com/en/coins/gram . Документация: https://docs.coingecko.com/reference/simple-price . Кеш 60 секунд, данные старше 180 секунд не используются. При ошибке провайдера новый счёт не выдаётся.

Счёт фиксирует сумму баланса в рублях, курс и количество nanoGRAM на 10 минут. Округление вверх до 1 nanoGRAM. Комиссия сети отдельно. Это пересчёт внутреннего баланса, не обмен криптовалюты на реальные рубли.

В кабинете при выборе способа GRAM показываются сумма, курс, срок, адрес и уникальный комментарий. Кнопка `t.me/sendgrams` открывает нативный GRAM-кошелёк Telegram с уже заполненными адресом и суммой. Пользователю нужно скопировать и вставить уникальный комментарий, поскольку обработчик Telegram пока не передаёт его в кошелёк. Кнопка проверки читает только свои счета. Без веб-кабинета доступны GRAM-кнопки в списке сумм Telegram-бота.

## Проверка и восстановление

Toncenter v3 проверяется каждые 15 секунд: транзакция получателя, mainnet-адрес, успешное выполнение, отсутствие bounce/emulation, подтверждение masterchain и комментарий из BOC. Суммы считаются в целых nanoGRAM. Клиентский хеш, скриншот и нажатие «Оплатил» не являются подтверждением.

Курсор кошелька сохраняется атомарно с найденными переводами; по 100 транзакций за проход, продолжение после перезапуска. Ошибка провайдера откатывает текущую страницу. Подтверждённый счёт зачисляется через общий атомарный механизм payment_receipts, с обновлением баланса, реферальными бонусами и очередями восстановления доступа/подтверждения. Хеши транзакций и ключи платежей уникальны. Повторная обработка не начисляет деньги повторно.

Перевод, попавший в блокчейн до истечения счёта, принимается даже при позднем обнаружении. Переплата зачисляет только заказанные рубли. Недоплата, перевод после срока и повторный перевод требуют ручной проверки; доплаты автоматически не суммируются. Перевод без нужного комментария не зачисляется автоматически.

## Админка

«Финансы → GRAM»: счета и последние 30 переводов, требующих проверки, с хешами транзакций. Поступления включаются в общую историю финансов, прогноз, результаты сообщений, число платящих пользователей и сводку пополнений. Возвраты выполняет владелец кошелька вручную после проверки; приложение не умеет выводить средства.

До боевого использования проверить маленьким реальным платежом: создание счёта → перевод с точным комментарием → «Оплачено» → однократное зачисление → восстановление доступа. Автоматические тесты не отправляют реальные деньги. При лимитах публичных API установить ключи, следить за ошибками `GRAM wallet scan will retry` и `GRAM processing will retry` в серверном журнале.
