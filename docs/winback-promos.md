# Персональный промокод для возвращения

Цепочка включена по умолчанию. Переключатель: **Настройки → Автоматические сообщения → Промокод на 5 дней для возвращения**. Текст: **Настройки → Тексты бота → Возвращение: персональный промокод на 5 дней**. Условия активации добавляются к редактируемому тексту автоматически.

- Баланс нулевой или отрицательный, ранее был подарок, пополнение или списание. Новый аккаунт с исходным нулём не получает код.
- Если не было первого онлайна/трафика, нет отдельного периода ожидания. Если VPN использовался — не раньше 48 часов после исчерпания баланса.
- Отправка проверяется в существующем цикле напоминаний (обычно каждые 2 минуты). Действуют тишина, незакрытые обращения, нерешённая проблема, пауза тарификации, обслуживание, блокировки, незавершённая оплата, лимиты 1 необязательного сообщения в сутки / 3 в неделю и ограничения повторов ошибок.
- Не чаще одного успешного предложения за **2 календарных месяца**. При ошибке отправки повторяется тот же код, новый не выпускается.
- Генерируется XXXX-XXXX-XXXX, только для получателя, одна активация, 7 дней. Кнопки: «Личный кабинет», «Главное меню». Проверка администратору доступна в тесте воронки; TEST-ONLY-CODE не создаёт действующего промокода.
- При первой попытке отправки фиксируются число обычных устройств и суточная цена. Минимум одно устройство, отдельный роутер не учитывается. Подарок равен `5 × число устройств × цена суток` в рублях. Изменение числа устройств впоследствии меняет срок расходования, но не сумму подарка.
- При активации текущий минус погашается **сверх** подарка. Пример: 2 устройства × 6 ₽ × 5 дней = 60 ₽; при балансе −13 ₽ начислится 73 ₽, после чего будет 60 ₽ до текущего суточного списания. Сразу запускается восстановление доступа; при недоступной панели его повторит плановый биллинг.
- Если после получения кода человек самостоятельно пополнил баланс, подарок остаётся доступным до истечения срока. Промокод не делает пользователя платящим и не запускает платёжные реферальные бонусы.
- В админском списке промокодов виден Telegram ID получателя. Условия автоматического подарка не редактируются задним числом; код можно архивировать. Удаление пользователя не превращает его код в общедоступный.

## Старые пользователи

Они участвуют без ограничения датой запуска. Миграция добавляет отслеживание перехода баланса из плюса в ноль/минус. Для уже исчерпанного баланса дата восстанавливается по истории операций после последнего положительного остатка. Если истории нет, отсчёт для пользовавшихся начинается с первого наблюдения после обновления: неизвестная дата не выдумывается. Не подключавшиеся не ждут эти 48 часов.

## Надёжность и проверка

Активация и обычных, и персональных промокодов теперь атомарна: использование кода, начисление, списание минуса и запись операции фиксируются одной транзакцией. Повтор запроса не начисляет второй бонус. В случае сбоя учёта вся операция откатывается, код можно повторить.

Изолированные PostgreSQL/WASM-тесты: `tests/test_winback_promos.py`. Запуск тем же способом, что описан в `docs/funnel-fixes-2026-10-01.md`, с `PGLITE_MODULE` и `NODE_BIN`. Проверяются обе группы, 48 часов, старые операции, устройства/роутер, чужой аккаунт, одноразовость, минус, 7 дней, 2 месяца, повтор отправки, откат, обычные промокоды и удаление владельца. Реальные Telegram-сообщения при проверках не отправляются.

Обновление сервера: `git pull --ff-only`, затем `docker compose up -d --build bot`. Новые поля, таблица, триггер и флаг создаются существующей инициализацией БД.
